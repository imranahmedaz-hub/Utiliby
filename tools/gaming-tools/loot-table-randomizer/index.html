How weighted loot tables work

In a weighted loot table, each item has a weight. The chance of an item being selected equals its weight divided by the sum of all weights in the table.

Chance (%) = (Item weight ÷ Total weight) × 100

For example, if your table has three items with weights 10, 20 and 30:

  • Item 1: 10 ÷ 60 = 16.67% chance
  • Item 2: 20 ÷ 60 = 33.33% chance
  • Item 3: 30 ÷ 60 = 50.00% chance

Weights do not need to sum to 100. The tool normalizes them automatically. This makes it easy to work with integer weights that reflect rarity tiers — for example, a rare item might have weight 1 while a common item has weight 100, meaning it is 100 times rarer.

Weighted random selection in game design

Weighted random selection is one of the most common mechanics in game design. It is used for loot drops, critical hit tables, random encounters, gacha pulls, drop rates in MMORPGs, card pack contents, crafting outcomes and much more. The reason is simple: pure equal random feels unfair — players expect common rewards to be common and rare rewards to be rare.

Designers tune the weights until the drop distribution matches their intent. This tool exposes those weights so you can test them before committing to them in code.

Loot box pity systems explained

A pity system guarantees a rare drop after a certain number of unsuccessful pulls. The mechanic is common in gacha games, mobile RPGs and live-service titles, where it protects players from prolonged bad luck. For example, a game might guarantee a 5-star character every 90 pulls, or a Rare item every 30 loot boxes.

This tool lets you set any pity threshold between 0 and 500 rolls. When you are within the pity window, the tool automatically upgrades the next drop to a Rare (or better) item. This is useful for simulating real loot box economies, testing player-friendly rates and understanding the true cost of a rare item.

Simulation mode: testing probability distributions

When you set a table of weights, you are setting a theoretical probability for each item. Simulation mode runs your table thousands of times and reports the actual drop frequency. This reveals:

  • Whether the weights produce the intended distribution
  • How much variance appears in small samples (1–100 rolls)
  • Whether a rare item is genuinely hard to obtain or has an unnoticed bug in the weights

For tabletop RPGs, simulation mode tells you whether your treasure table will produce the right balance of loot across a campaign. For video game design, it gives you a reality check before you commit weights to code.

Best practices for designing loot tables

  • Start with the player experience. What should feel common? What should feel special? Set weights to match.
  • Use integer weights. Small numbers are easier to reason about. "1 in 100" is clearer than "0.01".
  • Anchor a common item. Give the most common item a weight of 100, then scale the rest relative to it.
  • Test before shipping. Use simulation mode to verify the actual distribution matches your intent.
  • Add a pity system for rare items. Players hate long unlucky streaks — a pity mechanic softens the worst outcomes.
  • Review your table after live release. Real player behaviour often reveals problems that simulations miss.
