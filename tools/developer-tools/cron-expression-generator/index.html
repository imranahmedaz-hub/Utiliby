Cron syntax explained

Cron expressions are a compact way to describe a recurring schedule. A standard Unix cron expression has five fields separated by spaces:

FieldAllowed valuesSpecial characters
Minute0–59* , - /
Hour0–23* , - /
Day of month1–31* , - / ? L W
Month1–12 or JAN–DEC* , - /
Day of week0–7 or SUN–SAT (0 and 7 = Sunday)* , - / ? L #

The 6-field Quartz format used by Java schedulers, Spring, Jenkins and AWS EventBridge adds a seconds field at the start (0–59) and an optional year field at the end. Quartz also supports the special characters L (last), W (nearest weekday) and # (nth occurrence of a day), which standard Unix cron does not.

Day-of-month and day-of-week interaction

One of the most confusing aspects of cron is how the day-of-month and day-of-week fields interact. In standard Unix cron, when both fields are restricted (neither is *), the job runs when either field matches — not both. For example:

0 0 15 * 1

This does not mean "midnight on the 15th if it is a Monday". It means "midnight on the 15th of the month, OR midnight on any Monday". This is one of the most common sources of cron misconfiguration, and it is exactly the kind of thing this tool's plain-English explanation is designed to catch.

Quartz changes this behaviour: in Quartz, you must use ? in one of the two day fields to indicate "no specific value", and the job runs when the non-? field matches. This is one of the reasons the format matters.

Timezone: the silent source of cron bugs

Cron runs in the local timezone of the server it is installed on. On most cloud servers, that timezone is UTC. This means that a cron expression like 0 9 * * *, which the developer wrote thinking "9 AM my time", actually runs at 9 AM UTC — which could be 4 AM or 5 AM local time depending on the season.

This tool computes the next run times in the IANA timezone you select, so you can see exactly when the job will fire in the timezone you care about. If the times look wrong, the expression needs adjusting — or the server's timezone does. The next-run preview is the single most valuable feature for catching this class of bug before it reaches production.

Systemd timer equivalent

Modern Linux distributions use systemd, and systemd timers are the systemd-native alternative to cron. The syntax is different, but the schedules are equivalent. This tool generates the full [Timer] block alongside the cron expression, including:

  • OnCalendar= — the systemd schedule equivalent to the cron expression
  • Persistent=true — catches up on missed runs after a reboot, which cron does not do by default
  • RandomizedDelaySec= — avoids thundering-herd problems when many machines run the same job

For example, 0 9 * * 1-5 becomes:

[Timer]
OnCalendar=Mon..Fri *-*-* 09:00:00
Persistent=true
RandomizedDelaySec=30
[Install]
WantedBy=timers.target

Common cron mistakes

  • Timezone mismatch. The job runs in the server's timezone, not yours. Always check next run times in the target timezone.
  • Day-of-month and day-of-week OR logic. When both fields are restricted, Unix cron uses OR, not AND. Use ? in one field (Quartz) or a single field (Unix) if you mean AND.
  • Day-of-week numbering. Some systems use 0–6 with Sunday = 0; some use 1–7 with Monday = 1; some accept both. Use MON, TUE, etc. to avoid ambiguity.
  • Step value start point. */15 means "every 15 values starting from 0", not "every 15 minutes from the current time". In the minute field it produces 0, 15, 30, 45.
  • Missing command path. Cron has a minimal PATH. Always use absolute paths in the command part of a crontab line.
  • No output redirection. Cron emails the output of every job by default. Add >/dev/null 2>&1 if you do not want that.
  • Overlapping jobs. A job that takes longer than its interval will overlap with the next run. Use a lock file or a scheduler with overlap protection.

What is a free cron expression generator online?

How do I read a cron expression?

A standard Unix cron expression has five fields: minute, hour, day-of-month, month, day-of-week. For example, 0 9 * * 1-5 means at 09:00, Monday through Friday. The asterisk (*) means every value, slash-n means every n values, a comma means a list, and a hyphen means a range.

What is the difference between 5-field and 6-field cron?

Standard Unix cron uses 5 fields (minute, hour, day of month, month, day of week). Quartz and AWS EventBridge use 6 fields by adding a seconds field at the start. Quartz also supports an optional 7th year field and special characters like L (last), W (nearest weekday) and # (nth occurrence).

Why does my cron job run at the wrong time?

The most common cause is timezone mismatch. Cron runs in the server's local timezone by default, which is often UTC on cloud servers. If you write 0 9 * * * expecting 9 AM local time but the server is on UTC, the job runs at 9 AM UTC. Always preview next run times in the target timezone before deployment.

How do I get the next run time for a cron expression?

This tool advances a date minute by minute (with smart-skip optimisation for sparse schedules) and tests each candidate against the parsed cron fields. It shows up to 10 upcoming runs in your chosen timezone.

What does the asterisk mean in cron?

The asterisk (*) is a wildcard that matches every value for that field. In the minute field, * means every minute. Using * in all five fields means the job runs every minute of every hour of every day.

What does slash mean in cron expressions?

A slash followed by a number is a step value. */15 in the minute field means at minutes 0, 15, 30 and 45. 0-12/2 in the hour field means every 2 hours from hour 0 through hour 12.

How do I run a cron job every weekday?

Use the day-of-week field with a range: 1-5 means Monday through Friday (Sunday = 0 or 7). For example, 0 9 * * 1-5 runs at 9 AM every weekday. Use MON-FRI to avoid numbering ambiguity.

What is the systemd equivalent of a cron job?

Systemd timers use OnCalendar= instead of cron fields. 0 9 * * 1-5 becomes OnCalendar=Mon..Fri *-*-* 09:00:00. This tool generates the full systemd timer block including Persistent=true and RandomizedDelaySec.
