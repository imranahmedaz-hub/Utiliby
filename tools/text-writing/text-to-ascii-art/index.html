What is FIGlet?

FIGlet stands for "Frank, Ian and Glenn's LETters". It is a program written in 1991 that renders text as large ASCII banners. Each FIGlet font is a set of instructions that describes how to draw each character using printable ASCII. There are hundreds of FIGlet fonts in the wild, and FIGlet-compatible renderers are now used inside terminals, README generators, chat bots and package installers.

The fonts used by this tool are hand-built renderings in the spirit of the most popular FIGlet fonts. They cover the standard character set (A–Z, 0–9 and basic punctuation) and produce banners you can paste into any plain-text context.

Where to use ASCII art

  • README file headers. The most common use. ASCII banners give a GitHub or GitLab README a distinctive title that renders on any device.
  • Code comment blocks. Separate large sections of source code with an ASCII divider.
  • Terminal welcome banners. Print a banner when a script starts, a shell session opens, or a server connects.
  • Package installer output. Homebrew, npm postinstall scripts and CLI tools often print ASCII banners.
  • Chat bots and Discord messages. Bots send ASCII banners as greetings or status headers.
  • Retro text design. BBS systems, IRC, and old-school terminal aesthetics.
  • Bash and shell scripts. A quick divider at the top of a long script.

Tips for good ASCII art

  • Keep it short. Two words maximum for the wide fonts. Long text wraps and looks broken.
  • Match the font to the context. Use Block or Banner for serious projects; Doom or Graffiti for something playful.
  • Check the width. Most terminals are 80 characters wide. Keep your banner within that limit unless you know the reader has a wider display.
  • Use it sparingly. One banner at the top of a README is fine; a banner before every section is noise.
  • Wrap in a code block. In Markdown, put the banner inside triple backticks so it renders as monospaced text.
