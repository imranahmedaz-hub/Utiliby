    What is a free sitemap validator online?

    A free sitemap validator online is a tool that checks an XML sitemap for structural errors, protocol violations, size limits and SEO best-practice problems that could stop search engines such as Google and Bing from reading it properly. A sitemap is a file that lists the URLs you want crawled, so a broken one can waste crawl effort, delay indexing of new pages and leave important content out of search results.

    This validator checks a single XML sitemap, a sitemap index and every child sitemap it lists. It reads the file the way a strict parser would, then applies 87 rules covering the XML itself, the sitemaps.org namespace, URL and file limits, URL formatting, duplicates, lastmod dates, robots.txt conflicts, hreflang annotations and image, video and news extensions. You get a grade out of 100, a list of problems grouped by severity with a plain-language fix for each, charts, a table of files and a searchable inventory of every URL.

    It is built for SEO specialists, developers, site owners, agencies and anyone who has just launched a site, migrated a domain or turned on a sitemap plugin and wants to know whether the output is sound. Pasted text and uploaded files stay in your browser.

    Anatomy of an XML sitemap

    A basic sitemap is a urlset element holding one url element per page. Only loc is required. The XML declaration must be the very first thing in the file, with no blank line or space before it.

    <?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2026-10-01</lastmod>
  </url>
  <url>
    <loc>https://example.com/blog/first-post</loc>
    <lastmod>2026-09-18T08:30:00+00:00</lastmod>
  </url>
</urlset>

    Special characters inside a URL must be escaped as XML entities, so an ampersand becomes &amp;. Non-ASCII characters in paths should be percent-encoded. Use the same protocol and host that your canonical pages use.

    Sitemap index files explained

    A sitemap index is a parent file that lists child sitemaps. Use it when you pass 50,000 URLs, when a file gets close to 50 MB, or when you want to split by content type such as pages, posts, products and images. Each child is a sitemap element with a loc and an optional lastmod.

    <?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://example.com/sitemap-pages.xml</loc>
    <lastmod>2026-10-01</lastmod>
  </sitemap>
  <sitemap>
    <loc>https://example.com/sitemap-posts.xml</loc>
  </sitemap>
</sitemapindex>

    An index may not list another index, and the child files should be reachable on the same site. When you enter an index URL and keep Check child sitemaps on, the validator downloads each child (up to the number you set), validates it, and reports per-file results. It also finds URLs that appear in more than one child, which usually means a plugin is generating overlapping sitemaps.

    The most common sitemap errors and fixes

    1. Whitespace before the XML declaration

    A blank line or space before <?xml causes a parsing error such as "XML declaration allowed only at the start of the document". On WordPress this often comes from a plugin or theme file that prints output too early. Remove the characters before the opening tag and any closing PHP tag followed by blank lines.

    2. Missing or wrong namespace

    The root element must declare xmlns="http://www.sitemaps.org/schemas/sitemap/0.9". An https address, a typo or a missing declaration can cause a parser to reject the file or ignore the entries.

    3. More than 50,000 URLs or 50 MB

    Split the file and add a sitemap index. Compression does not help, because the limit applies to the uncompressed size.

    4. Relative or non-http URLs

    Every loc must be a complete address such as https://example.com/page. A path such as /page, a mailto: link or an empty tag is an error.

    5. Duplicate URLs

    The same address listed twice, or two forms that differ only by a trailing slash, point to a generator that is not deduplicating. Choose one canonical form.

    6. Mixed http and https, or several hosts

    List URLs that match your canonical protocol and host. A mix of http and https, or of www and non-www addresses, usually means redirects or canonical tags are not set up consistently.

    7. Invalid lastmod dates

    Values such as 01/10/2026 or 2026-10-01 09:30 (a time without a timezone) are not valid W3C datetime. Use 2026-10-01 or 2026-10-01T09:30:00+00:00.

    8. The same lastmod on every URL

    If every page carries the build time, search engines cannot trust the field. Google has said it uses lastmod only when it is consistently and verifiably accurate. Use the date the content last changed in a meaningful way.

    9. URLs blocked by robots.txt

    Listing a URL that robots.txt disallows sends mixed signals. Either allow it or take it out of the sitemap.

    10. Local, staging or private hosts

    URLs on localhost, private IP ranges or internal host names appear when a site is built from a development environment. Replace them with production addresses.

    11. A noindex or redirect URL in the sitemap

    A sitemap should list indexable, canonical pages that return a normal 200 response. This tool cannot request your pages, so confirm status codes and robots meta tags with a crawler or in Search Console.

    12. A sitemap that returns an HTML page

    If the address returns a login page, a custom 404 or a bot check, the response is not XML. The validator detects this and tells you the file is an HTML page.

    For changefreq and priority the tool checks that values are legal (the seven allowed words, and a number from 0.0 to 1.0) and notes that Google ignores them. Removing them keeps files smaller but is optional.

    Image, video, news and hreflang sitemaps

    Image sitemaps

    Each image:image needs an image:loc with an absolute address, and one URL entry may list up to 1,000 images. The tags image:caption, image:geo_location, image:title and image:license are deprecated in Google's documentation, and the validator flags them as information.

    Video sitemaps

    Each video:video needs a thumbnail location, a title, a description and either a content location or a player location. The description is limited to 2,048 characters, duration must be 1 to 28,800 seconds, rating 0.0 to 5.0, and the content and player addresses must differ from the page address. Yes/no fields accept only yes or no.

    News sitemaps

    News entries need the publication name and language, a publication date and a title. A news sitemap may hold up to 1,000 URLs and should list only recent articles, so the validator notes entries older than two days.

    hreflang in sitemaps

    Sites with several language or regional versions can list them with xhtml:link elements. Each URL should list all of its alternates including itself, use valid codes such as en, en-GB or x-default, use absolute addresses, and every alternate should link back. The validator checks all of this inside the file it is validating.

    Namespaces matter. Extension elements only count when their namespace address is exact. The image namespace ends in sitemap-image/1.1 and the video one in sitemap-video/1.1. A near-miss such as sitemap-image/1.0 makes the elements invisible to parsers, and the validator warns you.

    robots.txt and sitemap submission

    The simplest way to make a sitemap discoverable is a line in robots.txt such as Sitemap: https://example.com/sitemap.xml. The address must be absolute, and you can list more than one. In Fetch from URL mode the validator reads robots.txt, finds your Sitemap lines (which is also how it discovers sitemaps when you enter only a domain) and warns if the sitemap you entered is not listed.

    It also applies robots.txt rules to the URLs in the sitemap. Matching follows Google's documented behaviour: the most specific rule, meaning the longest matching path, wins, and when an Allow and a Disallow match equally, Allow wins. The * wildcard and the $ end anchor are supported. Choose Googlebot, Bingbot or all crawlers in Options.

    After you fix a sitemap, submit it in the Sitemaps report in Google Search Console and in Bing Webmaster Tools. Google retired its old sitemap ping address, so submission and robots.txt are the supported routes. Bing also supports the IndexNow protocol for instant URL notifications.

    Other sitemap formats: gzip, text, RSS and Atom

    • Gzip (.xml.gz). Allowed, and useful for saving bandwidth. The tool detects the gzip header, decompresses in the browser and checks limits on the uncompressed size.
    • Text sitemaps. A UTF-8 file with one URL per line. Valid, but cannot carry dates or media data.
    • RSS 2.0 and Atom 1.0. Google accepts feeds as sitemaps. The validator reads the links and applies the URL checks, and notes that dates and extensions were not examined.

    How the score and grade work

    The score starts at 100. Each type of error costs 15 points (up to 60) and each type of warning costs 4 points (up to 25), so one problem that affects 10,000 URLs does not count more than one that affects 10. If any file cannot be parsed or downloaded, the score is capped at 40. Information notes do not change the score.

    Sitemaps in WordPress, Shopify and other platforms

    Most platforms generate sitemaps for you, which means problems usually come from settings, plugins or caching rather than from hand-written XML. WordPress has included a built-in sitemap at /wp-sitemap.xml since version 5.5, and SEO plugins often replace it with their own index such as /sitemap_index.xml. Shopify serves an automatic /sitemap.xml index. Static site generators and frameworks typically need a plugin or a build step.

    • Run only one sitemap generator. Two plugins can produce overlapping files, which the cross-file duplicate check will reveal.
    • Exclude noindex pages, thin archives, internal search results and parameter URLs from the sitemap.
    • If a caching or security layer puts content before the XML declaration, clear the cache and exclude the sitemap URLs from minification.
    • After a domain or protocol migration, regenerate the sitemap so every URL uses the new canonical host.

    Why URL fetching can be blocked

    Web pages are only allowed to read files from another website if that website opts in using CORS headers. Most sitemaps are served without them, so a browser tool cannot always download your sitemap even though search engines can. When that happens the validator tells you so. Open the sitemap in a browser tab, select all, copy, and paste it into the Paste XML tab, or save the file and upload it. The same limit means the tool cannot read a robots.txt that is not CORS-enabled, which is why Options has a box to paste it.

    For the same security reason the tool does not request your page URLs to check their status codes. It validates the sitemap itself. Use Search Console's page indexing report or a crawler for live status checks.

    A sitemap audit workflow

    1. Validate the index (or the single sitemap) and fix every error first.
    2. Look at the file table. Any file near 50,000 URLs or 50 MB should be split soon.
    3. Review warnings: duplicates, mixed hosts, blocked URLs and identical lastmod values.
    4. Check the freshness chart. A sitemap with no recent dates on an active site suggests lastmod is not being updated.
    5. Download the issues CSV and share it with the developer or plugin owner.
    6. Re-run the validator after each fix, then submit the sitemap in Search Console and Bing Webmaster Tools.
    7. Check the Sitemaps report in Search Console a few days later for discovered URLs and any errors Google reports.

    Frequently asked questions

    What is a free sitemap validator online?

    A free sitemap validator online is a tool that checks your XML sitemap for structural errors, schema violations, URL limits and SEO best-practice issues that could prevent search engines like Google and Bing from crawling and indexing your site. This one runs in your browser and needs no sign-up.

    Why should I validate my XML sitemap?

    Search engines use XML sitemaps to discover your URLs. A malformed sitemap can be ignored, which wastes crawl effort, delays indexing and hides important pages from search results. Validation catches these problems before a search engine does.

    How do I validate a sitemap with this tool?

    Choose Fetch from URL, Paste XML or Upload file. For a URL, type a sitemap address or just a domain. Click Validate sitemap. You get a grade out of 100, a list of errors, warnings and notes with how to fix each one, charts, a file table and a URL inventory.

    What are the most common sitemap errors?

    The most common errors are whitespace before the XML declaration, a missing or wrong sitemaps.org namespace, more than 50,000 URLs in one file, relative URLs instead of absolute ones, mixed http and https addresses, duplicate URLs, invalid lastmod dates and URLs that robots.txt blocks.

    What is a sitemap index file?

    A sitemap index is a parent sitemap that lists other sitemap files. It is used when a site has more than 50,000 URLs or when you want to split sitemaps by section. Each child sitemap is listed with a loc tag inside a sitemap element. An index cannot list another index.

    How many URLs can a sitemap contain?

    Under the sitemaps.org protocol and Google's documentation, one sitemap file can hold up to 50,000 URLs and must not exceed 50 MB uncompressed. Larger sites split their URLs across several files and reference them from a sitemap index.

    Does this tool upload my sitemap to a server?

    No. Pasted text and uploaded files are parsed in your browser and are not sent to Utiliby. In Fetch from URL mode your browser requests the sitemap and robots.txt directly from the site you named, in the same way a browser tab would. Nothing is stored unless you tick Remember options, which saves only your option choices on this device.

    Why does Fetch from URL fail on some sites?

    Browsers only let a web page read another site's files if that site allows it with CORS headers. Most sites do not, so the request is blocked even though the sitemap is public. Open the sitemap in a new tab, copy the XML and use Paste XML, or save the file and use Upload file.

    What is a lastmod date and why does it matter?

    The lastmod tag tells search engines when a page was last modified. It must use W3C datetime format such as 2026-10-01 or 2026-10-01T09:30:00+00:00. Google says it uses lastmod only when it is consistently and verifiably accurate, so a real change date is better than the build time.

    Does Google use changefreq and priority?

    No. Google has said it ignores the changefreq and priority tags. They are allowed by the protocol and harmless, but you can remove them to keep the file smaller. This validator reports them as information, and checks only that their values are legal.

    What are sitemap image and video extensions?

    Extensions add media details to a URL entry. Image sitemaps use image:image with image:loc. Video sitemaps need a thumbnail, title, description and a content or player location. News sitemaps add publication details. The validator checks the required fields and the limits in Google's documentation.

    What does the hreflang check do?

    If your sitemap lists language versions with xhtml:link elements, the validator checks language codes, absolute href values, a self-reference on every URL, duplicate language entries and return links. If page A lists page B, page B should list page A.

    Can I validate a .xml.gz sitemap?

    Yes. Upload a .gz file or fetch a gzip-compressed address. The tool detects gzip from the file header, decompresses it in your browser and validates the XML. Size limits are checked on the uncompressed content.

    Can it check a whole sitemap index?

    Yes. Turn on Check child sitemaps in Options and the tool downloads each child sitemap listed in the index, up to the limit you choose, and validates it. You get one report with a per-file table and cross-file duplicate detection.

    Does it check robots.txt?

    In Fetch from URL mode it reads robots.txt, finds Sitemap lines, and flags a sitemap that is not listed. It applies Google's matching rules (the longest matching rule wins and Allow beats Disallow on a tie) to report listed URLs that robots.txt blocks. In other modes you can paste robots.txt into Options.

    Does the tool check if my pages return 200?

    No. A web page cannot check the status code of other sites' pages because of browser security rules, and this tool does not request the listed URLs. Use Google Search Console, Bing Webmaster Tools or a site crawler to find broken or redirected pages.
